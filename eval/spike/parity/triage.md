# Golden-graph CQ parity triage

The oracle uses the logical parameters recorded by `ComposeStats.query_parameters`: review-scoped values are full IRIs here and become bare `reviewId` values only at the Cypher boundary. Rows are compared as normalized sets, with the explicit column mappings in `eval/golden/expected_answers.json`; columns omitted from a mapping are binding-only presentation fields. The expected answers below come from the fixture's stated relationships and values, then the Oxigraph run was used only as confirmation. No new evidence quote was needed, so the composer continues to enforce the exact-substring rule against `eval/golden/works.json`.

**CQ01 — review roles by cluster.** The question asks for included works carrying the four role values in `analysis.inclusions`, grouped by the four hand-authored clusters and titled from `works.json`; the fixture has 29 such inclusion-role rows, and both bindings already returned 29. The root cause was not query semantics: the Cypher side's extra `issued`/`workIri` fields are binding presentation differences, so the oracle maps `workIri` to canonical `work`; the harness and LPG documentation now consistently use bare `kgqa-rag` for Cypher. The Cypher snapshot was already 29, so live confidence is high.

**CQ02 — seed main path.** Starting at `analysis.review.seed_value` (`arxiv:1706.03762`), the question asks for one direct citation edge between two review main-path inclusions, retaining an edge when either endpoint is the seed or the edge lies on a citation route to/from the seed; there is no publication-date straddle condition in the SPARQL. The composer’s nine `onMainPath` works are `L=LightRAG`, `G=GraphRAG`, `H=G-Retriever`, `O=Reasoning on Graphs`, `U=the Roadmap`, `R=RAG`, `D=DPR`, `B=BERT`, and `T=Transformer` (the seed). The 17 expected output edges are `T→R`, `T→U`, `T→B` (each admits because `ancestor = seed`); `R→G` (`G→R→T`), `R→U` (`U→T`), `R→D` (`D→R→T`), `R→H` (`H→R→T`), `G→L` (`L→G→R→T`), `U→O` (`O→U→T`), `D→R` (`R→T`), `D→O` (`O→U→T`), `B→R` (`R→T`), `B→U` (`U→T`), `B→D` (`D→R→T`), `O→U` (`U→T`), `O→H` (`H→R→T`), and `H→G` (`G→R→T`), where the bracketed route is the Cypher `newest-[:CITES*1..]->seed` witness. In contrast, `Lost in the Middle→G` and `CoT→H` are rejected because `Lost in the Middle` and `CoT` lack an `onMainPath` inclusion, even though the other endpoint is on the path; the old date predicate would also have wrongly rejected valid main-path edges such as `R→G` and `G→L` because their ancestor years are after the 2017 seed. The Neo4j snapshot’s 113 rows came from the prior variable-length path query, while the corrected Cypher now mirrors the SPARQL direct-edge and seed-reachability semantics; live confidence is high.

**CQ03 — methods for KGQA.** The question asks which methods are attached by `addresses` to the `knowledge-graph-question-answering` concept in `content.statements`, retaining sparse contributions with no result and reporting any `reports` result's dataset and metric; the fixture therefore gives 20 normalized method/work rows. Oxigraph's zero came from concepts being written to `content/default` while statements were in `content/golden-v02`; Neo4j's 15 also used the Cypher default for the hallucination problem, and the snapshot warning showed that `REPORTS` was absent. The composer now writes concepts to the extraction partition, the Cypher default is KGQA, SPARQL/Cypher both make result traversal optional, and Neo4j forward-merges `REPORTS`; live confidence is high, subject to server confirmation of the writer change.

**CQ04 — best result by dataset and metric.** The question selects the direction-aware best result for each dataset/metric among included review works; `analysis.inclusions` plus the result entries in `content.statements` produce five canonical rows, including the review's intended inclusion filter. Oxigraph's zero had the same content-partition defect; the Neo4j snapshot's seven rows came from the old unscoped query, which could choose results outside the review. The Cypher query now scopes both candidate and winning results through included `reviewId` inclusions, while the oracle maps Cypher `value` to SPARQL `bestValue` and ignores display-label columns. Live confidence is high.

**CQ05 — dense empty problem/method cells.** With `n=3`, the question asks for problem/method cells having no included contribution while both the problem row and method column have at least three distinct supporting works. The fixture's `addresses`, `proposes`, `uses`, and inclusion facts yield eight cells with the recorded support counts. Oxigraph's zero was caused by the aggregate comparison against a `VALUES` parameter plus the content partition mismatch; the Neo4j snapshot's ten rows were not review-scoped. The SPARQL query now filters an explicit support subquery, and the Cypher query applies `reviewId`/included filters to row, column, and negation paths; live confidence is high.

**CQ06 — recurring unaddressed limitations.** The three limitation entries in `content.statements` for `dpr`, `fid`, and `rag` share `hallucination-and-factuality`, so the expected row has count 3, oldest year 2020, and their exact fixture texts; no later included work addresses that same concept. Both sides were vacuous in the snapshot because the harness supplied different review representations; the Cypher file and writer now use `ADDRESSES_LIMITATION` with the documented bare review partition, and the shared parameters select the same review and `n=3`. The normalizer canonicalizes Neo4j's list projection to SPARQL's `GROUP_CONCAT` string without changing the query meaning. Live confidence is medium-high because Neo4j was not available.

**CQ07 — contradicted claims.** `content.statements` explicitly records Self-RAG claim 3 as contradicting RAG claim 3, and both works are included in `analysis.inclusions`, so the correct result is one claim-to-claim contradiction with the two exact claim texts and work titles. Both bindings were empty in the snapshot: the composer did not materialize `supports_claim`/`contradicts_claim`, and the Cypher side's warning reported no `CONTRADICTS_CLAIM` relationship. The composer now resolves those references, the Neo4j writer forward-merges the relationship, and both queries scope to the review; Cypher also returns the missing title fields so the mapping compares the same answer. Live confidence is high, conditional on the unrun writer path.

**CQ08 — uncompared method pairs.** The question operationalizes comparison as two included result-bearing methods having a result on a shared dataset; the fixture's included result statements produce 19 unordered method pairs with no shared dataset. Oxigraph's zero was the content-partition defect, while the Neo4j snapshot's 36 rows came from the old all-method/all-work query with no review/result scope. The Cypher query now derives candidates and the `NOT EXISTS` test only from included works in `kgqa-rag`, matching the review-scoped SPARQL query; the snapshot directly supports the old overcount diagnosis. Live confidence is high.

**CQ09 — fastest cluster growth.** `analysis.clusters` supplies four review clusters with their precomputed `growth_rate`, `top_concept`, and the concept fixture supplies `first_seen_in`, so the expected rows are the four rates `.84`, `.71`, `.62`, and `.18` with their first-seen works/dates. Oxigraph already returned four; Neo4j returned zero because the old query used the wrong review representation/traversal and concept nodes lacked the shared `Concept` label needed by the binding. The Cypher query now uses `reviewId`, `TOP_CONCEPT`, and `FIRST_SEEN_IN`, and the writer labels Problem/Method/Dataset/Metric nodes as both their specific label and `Concept`; live confidence is high.

**CQ10 — frontier non-peer-reviewed share.** The composer computes frontier components from the real citation graph and `analysis.inclusions`; 16 positive-frontier works are in scope and 15 have a non-`peerReviewed` source tier, so the expected share is `15/16 = 0.9375`. The fixture intentionally has no `publishedBy` organization facts, which explains Oxigraph's zero in the snapshot: its mandatory publisher join suppressed an otherwise meaningful share; Neo4j returned one row but with a list-shaped organization projection. The SPARQL publisher block is now optional and Cypher returns a scalar nullable organization, with the deprecation-prone subquery removed. Live confidence is high.

**CQ11 — close but citation-disconnected cluster pairs.** `analysis.cluster_pairs` contains pairs 1–4 (`.86`, zero cross-citations), 2–3 (`.78`, zero), and 1–2 (`.81`, two); at threshold `.75`, the expected answer is therefore the first two pairs. The Neo4j snapshot already had the correct two rows; the Oxigraph zero came from its graph-local parameter/`VALUES` behavior and the pair endpoint serialization path. The SPARQL file keeps the threshold binding inside the named graph, the Oxigraph parameter rewriter handles the two scopes, and the store emits/exports cluster endpoints as IRIs; Cypher retains the authoritative `CLUSTER_PAIR` relationship. Live confidence is high.

**CQ12 — assertion provenance.** The first Transformer contribution in `content.statements`, its evidence quote, and `content.extraction_run` define one expected provenance row: the exact abstract quote, Transformer work, curator model, prompt version, extraction activity, and end time. Oxigraph's snapshot rows were unfiltered because its old default assertion did not identify the fixture assertion; Neo4j returned zero because the writer/query contract lacked `FROM_WORK` and treated `ExtractionRun` differently from the stored Activity label. The SPARQL default and shared assertion parameter now use `.../contribution/arxiv-1706.03762/1`, the Cypher projection/order aliases are aligned, and Neo4j maps `FROM_WORK`, `WAS_GENERATED_BY`, and Activity export correctly. Live confidence is high but explicitly unconfirmed.

**CQ13 — excluded work reason and stage.** `analysis.inclusions` contains one exclusion for the seed Transformer work at `fulltext`, with the fixture reason “Foundational architecture paper; it does not directly study KGQA or RAG.” That is the expected single row. Oxigraph's three snapshot rows reflected the missing shared review/work parameter filtering, while Neo4j's zero was the full-review-IRI versus bare-`reviewId` mismatch. The harness now supplies both logical values to both bindings, and Cypher matches the bare partition while returning the full review IRI; live confidence is high.

**CQ14 — rejected gap hypotheses.** `analysis.gaps` marks only gap 3 as `user_status: rejected`, with its statement, RAG `about` concept, confidence `.69`, `partiallyAddressed` outcome, and rejection note, so the expected result is one row. Oxigraph already found that row; Neo4j's zero was the same review-id representation mismatch, and the Cypher snapshot carried no live row to contradict it. The Cypher query now matches `GapHypothesis.reviewId` with the shared bare review parameter and returns `about`/`verificationOutcome` plus the note, with ordering by the returned alias. Live confidence is high, pending the orchestrated Neo4j run.

All fourteen CQs are non-empty in the golden graph after these fixes. The separate SHACL violation counts were not used to drive this parity work.
